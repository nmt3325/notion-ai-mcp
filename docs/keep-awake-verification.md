# keep-awake 実通信検証（2026-09-08）

## 検証方法

隔離した GitHub Actions 環境で Chrome を起動し、提供された認証 Cookie で Notion にログインした。専用チャットをネイティブ UI から作成し、読み取り専用の MCP `env_list` を AI が1回ずつ繰り返すプロンプトを送信した。監視は自己登録させず、リポジトリの `NotionClient` と `createKeepAwakeSupervisor` を使う外部ハーネスで実行した。

実通信は、同じログイン済みブラウザの `fetch`（credentials: include）を経由した。外部 API の成功をモックしてはいない。サーバーの heartbeat / outcome / user-step、監視台帳、ブラウザの表示と通信メタデータを突き合わせた。実験中に通常のページや共有設定を変更する指示は出していない。

検証設定は idle 90秒・poll 5秒・cooldown 60秒。製品の既定 idle 120秒は変更していない。最初のベースライン観測のみ idle 60秒を使用した。

## 確認できたこと

| ケース | 観測結果 |
| --- | --- |
| 動作中 | heartbeat とツール結果が増加している間、ナッジは送られなかった |
| ロック中の送信 | 旧 `startChat` は即座に running を返し、約575ms後にジョブが失敗した。ブラウザ応答は HTTP 200・本文0 bytesで、inference lease による拒否だった |
| 修正版の拒否検出 | 同じ実スレッドで、保存確認付き送信が非同期の空ストリーム失敗を呼び出し側へ返した。送信済みとして扱わなかった |
| 自然停止 | `completed` でも最終ステップが未完の停止を2回観測した。step_count は409と407で、2000未満だった。これは今回観測した通常の途中停止であり、UIのステップ上限ボタンを検証したものではない |
| 修正版の自然停止からの再開 | heartbeat 停止から約98秒でナッジのユーザーステップが保存された。台帳の nudgeCount は1、anchorTime は保存されたユーザーステップの created_time と一致した。その後、MCP呼び出しが再開した |
| 最終版の中断からの再開 | 明示的な実験用中断後、約95秒でナッジを1件受領。その後ツール呼び出しが再開した。これは自然停止ではなく、制御した中断の検証である |
| 正常終了 | 「検証終了」を送信すると、AIは「通算255回。検証終了。」と応答した。約14秒後に監視が completed / turn_completed となり、ナッジ回数は1のままだった。255はAI側の最終カウンタ表示である |
| 終了後 | 最終更新から約172秒後にもメッセージ数801・ナッジ回数1のまま、実行中 lease なし、監視 completed を確認した |

ベースラインのロック中送信は、健康なターンに対する手動プローブだった。旧監視のカウンタ誤増加を実スレッドで発火させた、と混同しないこと。実際のサーバーファクトリとクライアントを結ぶ回帰テストでは、非同期拒否が監視へ伝わり、予算を消費しないことを別途検証した。

## 自動検証

新規回帰テストは22件。最初に追加した11件は未修正コードで全件失敗し、修正後は全件成功した。主な対象は以下。

- 登録・タイマー・手動チェックの競合、読み取り中の停止と遅延送信
- 最終ステップの欠損・読み取り失敗と、テキスト＋tool_use の混在
- 新しいユーザー発言や実行中 inference と古い完了情報の競合
- 送信前の heartbeat 再確認、確認中の期限切れ
- 空の HTTP 200 / HTTP エラーの伝播と、確認済み拒否後の中断・再送
- 最終回答を待たない保存確認、未確定の送信を再確認する際の重複抑制
- autoContinue 無効時の通常ナッジ、一般的な承認要求を自動承認しないこと

既存の永続化テスト1件は、固定された過去の日時が24時間の保持期間外になって失敗していたため、現在日時を使う fixture に修正した。製品の保持期間は変更していない。

## 範囲と制約

- 実通信の対象はネイティブ UI の workflow / inference-transcript チャット。別 transport の Agent Service やすべてのモデル組み合わせを検証したものではない。
- 今回はステップ上限の Continue ボタンを自然発生させてクリックする検証までは行っていない。既存の2992ステップの fixture、専用文言、予算・猶予・無効化の回帰テストは成功している。2000ステップの閾値は既存の推定であり、公式な停止理由の証明ではない。
- 未確定送信の重複抑制は、同一サーバープロセス内の保留IDによる。再起動をまたぐ exactly-once を保証するものではない。
- Cookie、個人・ワークスペース・チャットの識別子、私的な過去スレッド、認証ヘッダ、未加工の通信本文は、この検証記録やテスト fixture に含めていない。
- mainへの反映は稼働中MCPサーバーの再デプロイそのものではない。実運用へ適用するには、更新したコード／イメージでサーバーを更新・再起動する。
